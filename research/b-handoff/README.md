# System One Deslop agent package

Version 0.3, 13 October 2026.

Read `system-one-deslop-implementation-handoff.md` first. It is a first implementation brief for the repository scaffolding, with no assumption that an earlier question design has been implemented.

The architecture is Jev signal detection, reasoning-model interpretation and editing, followed by fresh assessment. Code owns evidence, routing, budgets, and preservation policy. Reader pleasure and reader value are separate outcomes; disappearing signals are not success.

The current catalogue has 13 bounded candidate questions, five initial pilot candidates, and 40 synthetic boundary examples. Every exact question is unvalidated. No Jev requests or reader studies have been performed. Only each definition's `question` object belongs in an API question map.

Files for implementation:

- `system-one-deslop-implementation-handoff.md` and `.docx`: the same current brief.
- `system-one-deslop-current-questions.md`: readable definitions, boundaries, and examples.
- `system-one-deslop-multipass-questions.json`: machine-readable questions, required state, examples, and evidence ancestry.

Research background:

- `research/full-research-dossier.md`: full original research snapshot, retained for the expanded source discussion.
- `research/astra-deslop-review.md`: full earlier review, including research qualifications and editorial recommendations.
- `research/astra-earlier-question-proposals.json`: historical reviewer proposals.
- `research/README.md`: how to interpret those background files.

The current handoff's evidence qualifications govern the implementation where they correct the original dossier. Earlier question suggestions in background research are not an additional implementation checklist.
